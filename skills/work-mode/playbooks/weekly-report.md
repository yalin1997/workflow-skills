# 工作週報：1–2 頁

1. 確認報告期間、讀者與既有公司版型；沿用上次版型，不每週重新設計。來源採指定任務、PR、驗證記錄及必要的既有工作紀錄。
2. 把活動轉為成果：解決什麼問題、帶來什麼影響、哪個證據支持。只選本週最重要的 3–5 項；一般讀者不需要逐次 commit 或逐日流水帳。
3. 明確區分「已完成」「PR 待審／待 CI」「進行中」「阻擋」。開 PR 不等於上線；沒有量測的效益採定性描述。
4. 使用精簡結構：本週重點、成果與證據、風險／需要協助、下週重點。必要時放一張小圖，不塞入完整技術文本。
5. 只做一輪事實、讀者與篇幅檢查。成果連回 PR／文件，避免重複分析。由人類確認優先順序、商業影響與對外措辭。
6. 交付 Markdown；若指定列印／PDF 版型且環境具備工具，在該版型實際檢查 1–2 頁。沒有固定渲染環境時，標記「篇幅依版型待確認」，不能以字數保證頁數。

建議版型：

```markdown
# 工作週報｜期間

本週最重要成果：一小段說明結果與價值。

| 成果 | 影響 | 狀態／證據 |
|---|---|---|
| | | |

風險與需要協助：只列需要注意或決定的事項。

下週重點：1–3 項明確結果。
```

不自動寄送、貼到聊天或公開發布。
