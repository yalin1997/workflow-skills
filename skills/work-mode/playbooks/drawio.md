# draw.io：可編輯且語意正確的圖

1. 確認圖要回答的問題、來源與版本、現況或提案，以及圖種類。以使用者指定的 `.drawio` 為主要交付，不以 Mermaid 或 PNG 取代。
2. 圖的語意分開處理：
   - **UML component：** 元件、責任、提供／需求介面及依賴方向；依賴線不拿來表示時間先後。
   - **資料流圖：** 外部實體、處理程序、資料儲存與具名資料流；一般 DFD 不稱為 UML。
   - **UML sequence：** 需要解釋互動時間順序、失敗或重試時才加入，避免一張圖混入所有語意。
3. 先整理少量節點與關係，逐一對照程式、介面或設計決策。未確認的關係標註假設；圖例說明任何自訂符號。
4. 用可用的本機檔案工具或核准的 draw.io 工具建立可編輯圖形、文字與連接線。可直接產出標準 `.drawio` XML；不以整張點陣圖嵌入作為可編輯交付。
5. 公司內容只能在已核准的本機 draw.io／站點處理。不得為方便而開啟未核准的 diagrams.net 雲端、外掛、字型服務或圖檔上傳服務；工具不可用時先產出檔案並記錄驗證缺口。
6. 做兩種檢查：
   - **結構與語意：** 檔案可解析、節點／連接線引用有效、名稱與方向吻合來源、元件圖與資料流圖彼此一致。
   - **實際呈現：** 在核准工具開啟或渲染，檢查遮擋、箭頭、標籤、可讀性及可編輯性。XML 可解析不代表視覺檢查通過；未開啟就明確說明。
7. 交付 `.drawio`、來源／假設摘要，以及有需要且能安全產出的 SVG／PNG 預覽。多種圖可分頁放在同一檔案；預覽是附件，原始檔保留可編輯性。
